# Ballpark Cribbage 121 — World Series Edition (v3)

This is the complete Node.js multiplayer baseball-themed cribbage project. A diamond-shaped pegboard, baseball pegs, stadium visuals, team-inspired branding and two illustrated historical-player decks have been added without changing the authoritative cribbage rules engine.

**Cleveland Indians / Guardians franchise history (seat 1)** and **Detroit Tigers franchise history (seat 2)** each have 52 different player names attached to their own 52 cards. There are eight original stylized portrait illustrations per franchise, which repeat as visual motifs; they are not verified likenesses. Official team logos are not included.

**Release status:** Finished and tested locally, **not publicly deployed**. To put two people on separate remote devices online, follow [`DEPLOY_ONLINE.md`](DEPLOY_ONLINE.md). Also see [`RELEASE_NOTES_v3.md`](RELEASE_NOTES_v3.md).

# Cribbage 121 — Online Multiplayer

A two-player, browser-based classic cribbage game built with **Node.js 20+**, built-in HTTP and Server-Sent Events (SSE). **No npm dependencies or paid API keys.**

## Features

- One person creates a private table; the second joins on a different phone/computer via a **six-character room code or invite link**.
- Live updates, private individual hands, a cribbage scoring board, starter cut, card-by-card pegging, and step-by-step hand counting.
- Authoritative server validates all moves, shuffles with cryptographic randomness, and computes points. The browser cannot decide points or access the opponent's unseen cards.
- Automatic reconnect using the original browser, both players can request a rematch.
- Responsive desktop/mobile interface, installable web-app manifest, and basic offline shell caching. **Playing requires an internet connection.**
- Scores and rooms saved to `data/rooms.json` by default (or set the `DATA_FILE` environment variable).
- Idle rooms expire after **7 days** without an action.

## Run on your computer

1. Install [Node.js](https://nodejs.org/) version 20 or later.
2. Unzip the folder and open a terminal inside `Cribbage_121_Online`.
3. Run `npm start` (or `node server.js`).
4. Open `http://localhost:3000` on the same computer.
5. To run the tests: `npm test`.

`PORT=4000 npm start` changes the port (PowerShell: `$env:PORT=4000; npm start`).

**Localhost is not a public invitation.** To play from separate devices over the internet, deploy the **Node.js server** to a public HTTPS host.

## Publishing to the internet (Render, Railway, Fly.io, VPS)

### Simple Render Web Service path

1. Create a new GitHub repository and upload all files from this project **at the repository root** (`server.js`, `game.js`, `package.json`, `public/`, etc.).
2. At Render, choose **New → Web Service**, connect your repository, and configure a **Node** application.
3. Build command: `npm install`. Start command: `npm start`. Node version: **20+**.
4. Deploy. Open the HTTPS address issued by the host. Share that address or an invite link generated by the app.
5. For room survival across instance restarts, use a persistent disk/volume with `DATA_FILE` pointing to a writable path, for example `/var/data/rooms.json`, **if your hosting plan supports persistent disks**.

`render.yaml` is included as a starting point. Host plan limits and pricing vary. Do not use a static-only website host for the Node backend.

### Other Node hosts

Any host that runs an always-on Node.js process and supports long-lived HTTP/SSE connections will work. Start `node server.js`, expose its assigned `PORT`, use **HTTPS** for public access, and if needed configure a persistent volume and set `DATA_FILE=/volume/rooms.json`.

**Important:** this version is designed for **one running server process**. Running multiple autoscaled instances without shared storage/message distribution will break room updates. Production at large scale would need a shared database and pub/sub channel.

## Rules implemented

- 121 points; the first player to reach or exceed 121 wins **immediately**. Skunk if loser is below 91.
- Lower-card cut wins first deal (ties recut); dealer alternates after each hand.
- Six cards each, two cards each into dealer's crib; non-dealer cuts the starter; Jack starter scores 2 for the dealer (“his heels”).
- Non-dealer begins pegging. Count must not exceed 31. Fifteen = 2; 31 = 2; pair = 2, three = 6, four = 12; pegging runs = number of cards; Go/last card = 1 except a 31 scores 2 instead.
- Non-dealer counts first, dealer second, dealer's crib last. Fifteens, pairs, multiple runs, flushes, and his nobs are calculated exactly; crib flush requires **all five** same suit.
- Automatic counting replaces manual claims, so **muggins** is not enabled in this version.

Rules reference: American Cribbage Congress, [How to Play Cribbage](https://www.cribbage.org/NewSite/about/CribbageBasics.pdf), and the ACC's [Tournament Rules](https://www.cribbage.org/NewSite/rules/rulebook_2025.pdf).

## File guide

- `server.js` — HTTP/SSE room server and storage, strict action endpoints.
- `game.js` — authoritative scoring and move-validation engine.
- `public/index.html`, `styles.css`, `app.js` — game interface.
- `public/manifest.webmanifest`, `sw.js`, icons — add-to-home-screen support.
- `test/` — scoring, full-match and server integration tests.

## Privacy and limits

- No login or public room directory. Room codes function as invitations; do not post them publicly.
- A private random player session token is saved in the browser for reconnects. Clearing browser storage can make your seat unrecoverable in this prototype.
- This is a recreational game prototype, not a hardened gaming platform, and has **no matchmaking, chat, spectator mode, payments, or wagering**.
- Games are stored on the server you host, not in the other player's browser. Back up the storage file if important.
